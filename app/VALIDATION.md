## F3 卡死对照与回归

- 旧版提交 9c59e98 在隔离实例中复现：一次 F3 输入后不断重复进入回调，每轮执行保存、注销和注册热键、更新菜单，45 秒外部超时终止。日志显示重复执行风暴，而非单个文件写入卡住。对照证据：项目根目录 .qa/run-1789655006030/hotkey-stages.log 和 timeout-main.json。
- 修复版将操作移出原生回调，只在焦点或热键配置变化时重新注册，合并待处理事件并取消过期操作。菜单关闭回调返回后才重建菜单。
- 真实 Windows F3 单次与连续 8 次追加切换、F1 和 Ctrl+Shift+F9 通过；原生托盘菜单通过 popUpContextMenu 打开、切回测试窗口关闭，设置和退出检查通过。未自动点击 Windows 通知区域中的实际右键入口。
- 测试窗口最小化后约 52 毫秒隐藏并释放热键；窗口重新激活不继承旧充能。22 项单元测试包含不重新注册、重复合并、失焦/退出/重新绑定取消、菜单延后更新。
- 使用独立配置运行，未修改用户配置；新功能及修复仍未发布新的 Release。

## 已解决的兼容问题

- 使用 Electron 4 支持的 `ready` 事件替换 `app.whenReady()`。
- 配置目录创建兼容 Node 10.11，不使用较新版本的递归 mkdir 选项。
- 退出时避免 iohook 0.9.2 的原生 unload 崩溃；停止事件分发并由 Windows 在应用退出时清理原生钩子。
